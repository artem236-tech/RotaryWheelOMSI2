# Rotary Wheel для OMSI 2 / openOMSI

Дополнение штатного ввода, не новый лаунчер. C# .NET 8, WinForms, Windows x64. Только steering передаётся в vJoy; педали и кнопки остаются на физическом геймпаде в игре. Драйверы и настройки игры программа НЕ устанавливает и НЕ меняет.

## Запуск

Открыть `dist/RotaryWheel.exe`. Нужен .NET Desktop Runtime 8 x64 (на проверенной машине установлен 8.0.28). Сначала включён безопасный режим «Только диагностика»: он читает реальный геймпад, но не создаёт выходное устройство. Подключите геймпад, обновите список, выберите XInput или DirectInput (один и тот же Xbox может отображаться дважды; предпочтителен XInput).

Выберите стик, отпустите его, нажмите «Калибровать отпущенный стик». Запустите: двигайте стик по окружности, затем отпустите — угол должен оставаться. Стик возле центра не меняет угол; первый отсчёт после выхода из мёртвой зоны только задаёт отправную точку. Это исключает ложное вращение при переносе пальца. Сглаживание меняет выход к накопленной позиции, НЕ возвращает его к нулю. Знак можно изменить инверсией.

Предел 900° означает **±900°**, то есть 1800° между упорами. Для 900° между упорами задайте 450°. Чувствительность 1: один оборот стика = 360° виртуального руля. Положительное математическое вращение против часовой стрелки повышает ось; при необходимости включите инверсию.

Центр: Ctrl+Alt+C (глобальная клавиша, о конфликте будет сообщение), кнопка окна/трея либо кнопка геймпада. Для XInput: 1=A, 2=B, 3=X, 4=Y, 5=LB, 6=RB, 7=Back, 8=Start, 9=LS, 10=RS; 0 отключает. Для DirectInput — номер кнопки от 1. Для правого DirectInput-стика выберите его реальные оси (обычно Rx/Ry, иногда Z/Rz). vJoy исключён из источников, чтобы избежать обратной связи.

## Подключение vJoy

1. Нужен уже установленный совместимый **vJoy x64**. Установка драйвера требует отдельного решения пользователя/прав администратора; утилита её не выполняет. В vJoy Configure включите отдельное устройство, например ID 1 и ось X. Не делите это устройство с другим feeder.
2. В утилите выберите `vJoyInterface.dll` x64 из доверенной установки vJoy. DLL не поставляется и не загружается из интернета автоматически. Укажите ID и ось, отключите «Только диагностика», запустите. Занятый/отсутствующий vJoy и выключенная ось дают явную ошибку.
3. В `joy.cpl` проверьте, что выбранная ось меняется круговыми движениями и удерживается при отпускании стика.
4. **Закройте игру и лаунчер. До изменения назначений скопируйте действующий `Inputs/gamectrler.cfg` и `settings.cfg` в файлы с суффиксом `.before-rotary.bak`.** В штатном интерфейсе контроллеров назначьте **Steering только оси vJoy**, уберите Steering с физического Xbox/DirectInput. Газ, тормоз, обзор и кнопки физического геймпада оставьте. Не отключайте устройство целиком. У vJoy не назначайте педали, если они физические. Перезапустите игру после сохранения.
5. Проверяйте на стоящем автобусе: полный круг в обе стороны, отпускание, кнопка центра, отсоединение и подключение. Если игра продолжает центрировать или рулить от левого стика, есть конфликт штатного gamepad-профиля/второго назначения: сама утилита его не подавляет. Не скрывайте геймпад через HidHide — иначе исчезнут штатные педали/кнопки.

Не запускайте второй feeder одновременно. При пропадании геймпада запись прекращается, последний выход остаётся, восстановление начинает новый угловой отсчёт. Явный сброс разрешён и без геймпада. При закрытии/ошибке утилита освобождает vJoy; **драйвер может применить свои начальные значения при освобождении или перезапуске устройства**. Это не гарантия удержания при аварии ОС/драйвера. Перед остановкой поставьте автобус на тормоз и выйдите из поездки. Положение между запусками не сохраняется: новая сессия начинает с центра.

## Настройки и журнал

`rotary-wheel.json` рядом с exe, сохранение атомарной заменой, предыдущий вариант `.bak`. Настройки применяются при новом запуске передачи. Частота 125–250 Гц (по умолчанию 250), отдельный поток, таймер Windows 1 мс и короткое ожидание по Stopwatch; фактическая частота показана в окне. Это не система реального времени: нагрузка игры/диска может снизить частоту. После паузы >100 мс угловая база сбрасывается, а не угадывает пропущенные обороты. Движение более 180° между отсчётами неразличимо принципиально.

`rotary-wheel.log` содержит UTC, подключение/ошибки и при включённой трассировке каждый отсчёт: connected, x, y, radius, angle (радианы), delta (радианы), wheelAngle (градусы), output [-1,1]. Буфер сбрасывается раз в 250 строк; ротация около 8 МиБ, одна предыдущая копия. Выключите подробный журнал после проверки, чтобы уменьшить нагрузку диска.

## Что обнаружено в приложенной игре

- Приложена бинарная папка `openOMSI-0.1.929-server-windows-x64`; `start.cmd` запускает dedicated server через `--root ... --server ...`. Нет локальных исходников лаунчера, SDK или документированного фильтра аналогового ввода.
- Фактический `C:/Users/артём/.openomsi/game.log` сообщает **openOMSI 0.3.52, build 41d69ab**, запуск из `E:/openOMSI-0.1.929-server-windows-x64`, корень оригинальной игры **E:/OMSI 2**. Имя папки не доказывает версию бинарника.
- Найдены `E:/OMSI 2/Inputs/gamectrler.cfg` (старые профили SideWinder/G25/CH/MOMO) и `C:/Users/артём/.openomsi/Inputs/gamectrler.cfg` (дополнительно vJoy Device и Xbox 360). В профиле openOMSI vJoy X уже имеет функцию 0 (руль), Xbox X тоже имеет 0; это возможный конфликт, не доказательство фактического приоритета движка. Газ/тормоз Xbox и кнопки нельзя удалять вместе со Steering.
- `C:/Users/артём/.openomsi/settings.cfg`: ключи `pad_steer_linear`, `pad_steer_speed`, `pad_deadzone`, `pad_steer_smooth`, `steering_linear`, `wheel_range`, `wheel_lock`, `right_stick_look`. Это параметры штатной обработки, но не язык скриптов для atan2/накопления. В Documents/OMSI 2 конфиги не обнаружены. Оригинальные логи содержат предупреждения отсутствующего контента; утилита их не исправляет.
- Современный публичный загрузчик выбирает более новый профиль из `.openomsi/Inputs` и папки контента, затем оригинальный. Поэтому активный путь надо сверять с конкретной версией; одного существования файла недостаточно. Для v0.1.929 правила отличаются.
- Lua/OMSI DLL поддерживаются, но универсальный установщик/фильтр steering не подтверждён. Запись переменной скрипта конкретного автобуса не равна подмене оси. Патч бинарника не выполнялся. Выбран внешний vJoy-мост: он сохраняет штатную обработку остальных органов управления и подходит оригинальной OMSI 2.
- ViGEm не реализован: требуется один из vJoy/ViGEm, выбран vJoy как абсолютная DirectInput-ось. Эмуляция ещё одного Xbox создаёт дополнительный gamepad-профиль и риск штатного автоцентра. Интерфейс не обещает несуществующего выбора ViGEm.

Источники исследования: локальные README/start.cmd, оба gamectrler.cfg, settings.cfg, game.log; публичные `https://github.com/openOMSI-org/openOMSI/blob/v0.1.929/docs/PLUGINS.md`, `crates/omsi-app/src/controllers.rs`, современный `crates/omsi-input/src/controllers.rs`; vJoy SDK `https://github.com/shauleiz/vJoy/blob/master/SDK/inc/vjoyinterface.h`. Исследователь отдельно сверил API релиза 0.1.929. Совпадение локальных бинарников с релизом по хешу не проверялось.

## Разработка и проверки

```
dotnet build RotaryWheel -c Release
dotnet run --project RotaryWheel.Tests -c Release
dotnet publish RotaryWheel -c Release -r win-x64 --self-contained false -o dist
dotnet dist/RotaryWheel.dll --probe
dotnet dist/RotaryWheel.dll --smoke-test
```

Исходники: `Core/WheelEngine.cs` не зависят от Windows/устройств; `Devices` — XInput, DirectInput, vJoy; `BridgeRunner.cs` — опрос; `Form1.cs` — UI; `BridgeConfig.cs` — JSON. DirectInput использует SharpDX.DirectInput 4.2.0 (архивная библиотека, изолирована в адаптере; обновление на поддерживаемую обёртку — отдельная техническая задача). NuGet lockfile закрепляет версии. Тесты — исполняемый набор регрессионных утверждений без стороннего тестового раннера, завершение ненулевым кодом при ошибке.

Фактически выполнено: Release-сборка без предупреждений/ошибок, публикация win-x64, `PASS: 21 regression assertions`, `PASS: WinForms constructed, shown and closed`. Изображение настоящего окна осмотрено: настройки и кнопки доступны. `--probe` завершился `PROBE COMPLETE` без устройств: на момент проверки геймпад не обнаружен. Независимый обзор кода выявил и помог исправить границы JSON/UI, обработку ошибки закрытия журнала, ложный сброс при переподключении с удержанной кнопкой и проверку NaN в тестах. Отдельный исполнитель проверок недоступен; команды проверены основным инженером.

Сборка и тесты алгоритма не доказывают передачу в OMSI. Аппаратная приёмка требует физического геймпада, установленного vJoy и поездки. WinForms не является веб-страницей: браузерная проверка к нему неприменима; smoke-test открывает настоящее окно и сохраняет его изображение для осмотра.
